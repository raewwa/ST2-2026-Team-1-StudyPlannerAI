# AI Study Planner — Седмица 2, стъпка 1/5

Flask MVC проект за **Софтуерни технологии 2**. **Няма AI интеграция** — тя е предвидена за Седмица 5.

## Стартиране

Изисква Python 3.10+ и интернет за Bootstrap CDN ресурсите.

```bash
python -m venv .venv
# Windows PowerShell: .venv\Scripts\Activate.ps1
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements.txt
python run.py
```

Отвори http://127.0.0.1:5000. SQLite базата се създава в `instance/`. Копирай `.env.example` като `.env` и задай собствен `SECRET_KEY` за употреба извън локална разработка.

## Реализирано през Седмица 1

- **MVC:** `app/models` (Subject), `app/controllers` (Flask Blueprint), `app/templates` (Jinja2 Views).
- **7 маршрута:** Dashboard и Subjects работят; Tasks, Exams, Schedule, Login, Register са начални страници.
- **SQLite / INSERT:** `POST /subjects` добавя предмет; името е задължително (до 120 символа), семестърът е 1–12 или празен, описанието е до 1000 символа.
- **SELECT with Filter:** `GET /subjects?search=математика&semester=2` комбинира нечувствително към регистъра търсене по име и точно съвпадение на семестър. Параметрите могат да се ползват поотделно; празните филтри показват всички.
- **Валидация:** HTML ограничения, backend валидация, CSRF защита на POST. Невалидни GET филтри показват съобщение и нулев резултат.
- **Singleton pattern:** `app/patterns/app_settings.py` съдържа `AppSettings` — една неизменяема инстанция с константи за търсенето/семестрите, защитена с `Lock` при създаване. `AppSettings() is AppSettings()` е `True`. Не използваме Singleton за SQLAlchemy сесиите: тях ги управлява Flask-SQLAlchemy.
- **UI:** Bootstrap 5, Bootstrap Icons, без емотиконки в `base.html` и `dashboard.html`, палитра `#bee9e8`, `#62b6cb`, `#1b4965`, `#cae9ff`, `#5fa8d3`.
- **Тестове:** начални smoke тестове, INSERT/валидация/CSRF, филтриране, SQL wildcard символи и Singleton.

## Как да демонстрираш седмица 1

1. Стартирай приложението и отвори **Предмети**.
2. Добави „Математика“ (семестър 1), „Математика II“ (семестър 2), „Физика“ (семестър 2).
3. Потърси `математика` — виждаш двата предмета.
4. Избери семестър `2` — виждаш „Математика II“ и „Физика“.
5. Комбинирай търсене `математика` + семестър `2` — виждаш само „Математика II“.
6. Натисни **Изчисти**, за да върнеш всички записи.
7. Покажи Singleton класа и теста `test_singleton_identity_immutable_and_values`.

## Седмица 3 — Стъпка 3/4: Repository Pattern

**Repository Design Pattern** е реализиран в `app/repositories/`:

- `OwnedRepository` — общ интерфейс за `query`, `get_or_404`, `add`, `update`, `delete`, `exists`.
- `SubjectRepository` — предмети на текущия потребител.
- `TaskRepository` — задачи и комбинирани филтри.
- `ExamRepository` — изпити по дата и час.
- `StudySessionRepository` — седмичен график и проверка за припокриващи се интервали.

Контролерите в `app/controllers/main_controller.py` използват тези класове за
CRUD операциите, вместо директно да изграждат SQLAlchemy заявки. Всеки
repository получава изрично `current_user.id` и ограничава четенето,
редактирането и изтриването до собствените записи. При опит за достъп до
чужд запис `get_or_404` връща HTTP 404. `add` не приема потребителски
`user_id` от HTML формите.

При грешка при запис контролерът прави `db.session.rollback()` и показва
съобщение, както в предходните версии. Изключение е смяната на статуса
на задача, където контролерът променя само един атрибут и извършва commit.

**Поправен тест:** `tests/test_week3_step2.py::test_owner_isolation` вече
проверява за реални елементи `data-session-id`, вместо за думата
„Преговор“, която присъства и в placeholder на формата.

**Нови тестове:** `tests/test_week3_step3.py` — CRUD и owner isolation
за repository класовете, филтриране и проверка за припокриване.
